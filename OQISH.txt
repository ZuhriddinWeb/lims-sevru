NIMA QO'SHILDI
---------------------------------------------------------------------------
 Administratsiya → «Markaziy portal» sahifasi (faqat admin / central.manage):
  • Markaz manzili (masalan http://192.168.14.23:5000) va portal bergan «Ulanish kaliti».
    Kalit bazada shifrlangan saqlanadi, qayta ekranga chiqmaydi (faqat oxirgi 4 belgi).
  • Qaysi bloklar ketishini admin belgilaydi:
      sukut bo'yicha YOQIQ: umumiy ko'rsatkichlar, 30 kunlik dinamika, ish oqimi,
                            smenalar, uskunalar tayyorligi;
      sukut bo'yicha O'CHIQ: ishchi varaqlar, buyurtmalar, guruhlar yuklamasi,
                            buyurtmachi bo'limlari (nomlari bilan ketadi).
  • Namuna shifrlari, natija qiymatlari, foydalanuvchilar — HECH QACHON yuborilmaydi
    (faqat sonlar va jamlangan ko'rsatkichlar).
  • «Nima ketishini ko'rish» — portalga aynan nima ketishini JSON ko'rinishida ko'rsatadi.
  • Oraliq: 5 / 10 / 15 / 30 / 60 daqiqa. «Hozir yuborish» tugmasi.
  • Holat: oxirgi yuborish vaqti, natija, xato matni, ketma-ket xatolar.
 Har yuborish HMAC-SHA256 bilan imzolanadi; portal soxta/eskirgan so'rovni qabul qilmaydi.
 Bazaga yangi jadval YO'Q (sozlama app_settings ga yoziladi). Migratsiya kerak emas.

1. LOKAL KOMPYUTERDA (E:\ai projects\lims-sevru)
---------------------------------------------------------------------------
  1) Zip ichidagi fayllarni loyiha ildiziga yoying (ustiga yozish — «Ha»).
     OQISH.txt ni loyihaga qo'shmang.
  2) npm run build
  3) Tekshirish:  powershell -ExecutionPolicy Bypass -File deploy\tekshir_versiyalar.ps1
       → «public\build: Paket 44 bilan yig'ilgan» chiqishi kerak.
  4) git add -A
     git add -f public/build
     git commit -m "Paket 44: markaziy portalga uzatish"
     git push

2. HAR BIR ZAVOD SERVERIDA
---------------------------------------------------------------------------
  Administrator cmd, loyiha papkasida:
     git log -1 --oneline            (hozirgi holatni yozib qo'ying)
     git fetch
     git reset --hard origin/main
     deploy\server_yangilash.bat
  (yoki qo'lda:  php artisan lims:upgrade   va   php artisan optimize:clear)
  lims:upgrade faqat CentralLinkSeeder ni qo'shadi: central.manage ruxsati va menyu.
  Mavjud ma'lumotga tegmaydi.

  MUHIM: «LIMS Scheduler» (Windows Task Scheduler, har daqiqada schedule:run) ishlashi
  shart — avtomatik yuborish shu orqali. server_yangilash.bat uni tekshiradi.

3. ULASH (har zavod uchun bir marta)
---------------------------------------------------------------------------
  a) Portalda (192.168.14.23:5000/admin) → Laboratoriyalar → kerakli zavod → «Kalit yaratish».
     Kalit FAQAT bir marta ko'rsatiladi — nusxa oling.
  b) Zavod LIMS'ida → Administratsiya → Markaziy portal:
       Manzil:  http://192.168.14.23:5000
       Kalit:   (nusxalangan kalit — ngmk1.<raqam>.<…>)
       «Nima yuboriladi» bloklarini belgilang → «Markazga yuborish yoqilgan» → «Saqlash» → «Hozir yuborish».
     «Markazga yuborildi» chiqsa — portal bosh sahifasida zavod «Onlayn» bo'ladi.
  Tekshirish buyrug'i (serverda):  php artisan central:push --force --show
