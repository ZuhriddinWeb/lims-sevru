 2. SQL SERVER: BO'SH BAZA VA LOGIN
---------------------------------------------------------------------------
 SQL Server «Mixed Mode» (SQL Server and Windows Authentication) va TCP/IP yoqilgan bo'lsin
 (SQL Server Configuration Manager; o'zgargach xizmatni qayta ishga tushiring).

 deploy\baza_yaratish.sql ni oching, 3 qiymatni almashtiring:
      lims_yangi   baza nomi          lims_user   login          KUCHLI_PAROL   parol (12+ belgi)
 Ishga tushirish:
      sqlcmd -S localhost -E -C -i deploy\baza_yaratish.sql
 (SSMS da ochib Execute ham bo'ladi. Nomlangan nusxa:  -S localhost\SQLEXPRESS)
 Tekshirish:
      sqlcmd -S localhost -U lims_user -P KUCHLI_PAROL -d lims_yangi -C -Q "SELECT DB_NAME()"

 Baza collation'i boshqa serverlardagi bilan bir xil bo'lsin:
      SELECT name, collation_name FROM sys.databases;
 Mavjud bazani ishlatmang — LIMS uchun alohida bo'sh baza.

 7. IIS: SAYT, RUXSATLAR, web.config
---------------------------------------------------------------------------
 Sayt papkasi = loyihaning  public  papkasi (loyiha ildizi emas!).

      %windir%\system32\inetsrv\appcmd add apppool /name:LIMS /managedRuntimeVersion:""
      %windir%\system32\inetsrv\appcmd add site /name:LIMS /bindings:http/*:80: /physicalPath:C:\inetpub\lims\public
      %windir%\system32\inetsrv\appcmd set app "LIMS/" /applicationPool:LIMS
 (Default Web Site 80-portni egallagan bo'lsa — to'xtating yoki LIMS ga boshqa port/host bering.)

 web.config:
      if not exist public\web.config copy deploy\web.config.example public\web.config

 Yozish ruxsatlari (usiz «500» yoki bo'sh sahifa):
      icacls storage         /grant "IIS AppPool\LIMS":(OI)(CI)M /T
      icacls bootstrap\cache /grant "IIS AppPool\LIMS":(OI)(CI)M /T

 HTTPS: IIS Manager → sayt → Bindings → https. So'ng .env da APP_URL va CORS_ALLOWED_ORIGINS
 ni https ga o'zgartirib: php artisan optimize:clear.   Firewall: 80/443 ochiq bo'lsin.

 7A. XAMPP / APACHE  (IIS o'rniga — hozirgi serverlardagidek)
---------------------------------------------------------------------------
 Sayt papkasi = loyihaning  public  papkasi. Mavjud ishlab turgan serverdagi Apache sozlamasini
 (C:\xampp\apache\conf\extra\httpd-vhosts.conf va httpd.conf dagi Listen) nusxalash eng oson.
 Namuna (port 3010):
      httpd.conf:          Listen 3010
      httpd-vhosts.conf:
         <VirtualHost *:3010>
             DocumentRoot "C:/xampp/htdocs/LIMS/public"
             <Directory "C:/xampp/htdocs/LIMS/public">
                 AllowOverride All
                 Require all granted
             </Directory>
         </VirtualHost>
 mod_rewrite yoqilgan bo'lsin (httpd.conf: LoadModule rewrite_module …, XAMPP'da odatda yoqilgan);
 public\.htaccess repoda bor. php.ini — C:\xampp\php\php.ini (1.2 dagi qatorlar, ayniqsa zip va
 pdo_sqlsrv). Apache'ni xizmat sifatida o'rnating (XAMPP Control Panel → «Svc» belgisi) — server
 qayta yonganda o'zi ishga tushadi. O'zgartirishdan keyin: Apache Stop → Start.
 Firewall: tanlangan port ochiq bo'lsin. .env da APP_URL va CORS_ALLOWED_ORIGINS — shu port bilan.

 8. REJALASHTIRGICH (Task Scheduler)
---------------------------------------------------------------------------
 Har daqiqada  php artisan schedule:run. Usiz ishlamaydi: laboratoriyalararo sinxronlash
 (har daqiqa), buyurtma muddati (har soat), kalibrovka eslatmalari (07:00). Qolgani ishlaydi.

 Skript so'raganda «ha» — o'zi yaratadi. Qo'lda (Administrator cmd):
      schtasks /Create /TN "LIMS Scheduler" /SC MINUTE /MO 1 /RU SYSTEM /RL HIGHEST /F /TR "\"C:\php\php.exe\" \"C:\inetpub\lims\artisan\" schedule:run"
 XAMPP:
      schtasks /Create /TN "LIMS Scheduler" /SC MINUTE /MO 1 /RU SYSTEM /RL HIGHEST /F /TR "\"C:\xampp\php\php.exe\" \"C:\xampp\htdocs\LIMS\artisan\" schedule:run"
 Tekshirish:
      schtasks /Query /TN "LIMS Scheduler"
      php artisan schedule:list      → interlab:sync, sample-requests:expire, lims:check-reminders

 10. XATOLAR JADVALI
---------------------------------------------------------------------------
 «Bu bazada foydalanuvchilar bor — ISHLAB TURGAN server»
      .env boshqa (ishlab turgan) bazaga qarab turibdi — DB_DATABASE ni tekshiring.
      Haqiqatan ham shu server bo'lsa — SERVERGA_YANGILASH.txt.
 «Bazada boshqa dasturning jadvallari bor»
      LIMS uchun alohida bo'sh baza yarating (2-bo'lim), DB_DATABASE ni o'zgartiring.
 «could not find driver»
      pdo_sqlsrv yoqilmagan yoki PHP versiyasiga mos emas (nts/x64/83). IIS boshqa php.ini
      ishlatishi mumkin: php --ini va phpinfo() ni solishtiring.
 «SQLSTATE[08001] … certificate» / SSL
      .env: DB_TRUST_SERVER_CERTIFICATE=true
 «Login failed for user»
      Mixed Mode yoqilmagan, parol xato yoki login bazaga biriktirilmagan (2-bo'lim).
 ulanish vaqti tugadi
      TCP/IP yoqilmagan, 1433 yopiq, DB_HOST xato; nomlangan nusxada DB_PORT ni o'chiring.
 «public\build yo'q yoki eski»
      lokalda npm run build va git add -f public/build unutilgan.
 IIS «500» yoki bo'sh sahifa
      storage va bootstrap\cache ruxsati (7-bo'lim); storage\logs\laravel-*.log; APP_KEY.
 IIS «404» har sahifada
      URL Rewrite moduli yoki public\web.config yo'q.
 API «CORS» / tarmoq xatosi
      .env: CORS_ALLOWED_ORIGINS ga sayt manzili; php artisan optimize:clear.
 Rasm/fayl ochilmaydi (404)
      php artisan storage:link  (yoki mklink /J public\storage storage\app\public).
 Natija kiritishda 404
      .env da DB_INTEGER_IDS=false — o'chiring, optimize:clear.
 «Serverda PHP zip kengaytmasi yoqilmagan» (Excel)
      php.ini: extension=zip ; Apache Stop/Start (IIS: iisreset). php -m | findstr /i zip
 Yordamchi javob bermaydi
      lims:upgrade bajarilganmi (help:import); HELP_ENABLED=true; optimize:clear; Ctrl+F5.
 Skript o'rtada xato bilan to'xtadi
      Xatoni tuzatib, skriptni qayta ishga tushiring — chala o'rnatish davom ettiriladi.
      Hali hech narsa kiritilmagan bo'lsa, bazani DROP/CREATE qilib boshidan boshlash ham mumkin.
